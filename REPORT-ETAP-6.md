# Этап 6: два блока по макету Figma

## Что исправлено

Вёрстка сверена с [исходным макетом](https://www.figma.com/design/kj62pS6OrwQBLL9Ch3HYI6/angular-design?node-id=1-291).
Раньше в этих секциях были придуманные тексты, карточки маршрутов и одна повторяющаяся фотография.
Теперь структура и содержимое соответствуют двум блокам из задания:

- «О нашем походе»: две фотографии слева, заголовок и описание справа.
- «Лучшие программы для тебя»: три преимущества слева, четыре фотографии справа.

Также исправлены шапка и первый экран: логотип, фотография, шрифты, высота первого экрана,
выравнивание заголовка, прозрачные поля формы и отступы.

Ссылка выделяет карточки следующей секции «Популярные направления». Два блока из текущего
задания находятся выше неё. Карточки маршрутов не относятся к блоку «Лучшие программы для тебя».

## 1. Как устроена страница

В `src/app/app.component.html` компоненты идут в таком порядке:

```html
<app-navbar />
<app-hero />
<app-about-hike />
<app-programs />
<router-outlet />
```

Компонент — отдельная часть интерфейса. Здесь у каждой секции три файла:

| Файл | За что отвечает |
| --- | --- |
| `.component.ts` | Класс компонента, его настройки и данные |
| `.component.html` | Разметка, которую Angular показывает в браузере |
| `.component.scss` | Размеры, цвета, расположение элементов и анимации |

В `@Component` свойство `selector` задаёт имя HTML-тега компонента, `templateUrl` указывает
на шаблон, `styleUrl` — на стили. В `AppComponent.imports` перечислены компоненты, которые
используются в его шаблоне. Это структура standalone-компонентов: отдельный `NgModule` здесь не нужен.

Стили компонента Angular ограничивает его шаблоном. Поэтому стили кнопки из секции «О нашем
походе» не применяются автоматически к кнопке в другом компоненте. Нужные правила есть в обоих
SCSS-файлах. Общий шрифт и сброс отступов находятся в `src/styles.scss`.

## 2. Блок «О нашем походе»

Файлы находятся в `src/app/about-hike/`.

В `AboutHikeComponent` нет данных и методов: содержимое этой секции статическое и находится
непосредственно в HTML. Пустой класс для такого компонента — нормальная ситуация.

### Две колонки

```scss
.about__inner {
  display: grid;
  grid-template-columns: 480px 1fr;
  gap: 120px;
  max-width: 1180px;
  margin: 0 auto;
}
```

`display: grid` включает CSS Grid. Первая колонка имеет ширину 480 px, а `1fr` отдаёт второй
колонке оставшееся место. В контейнере 1180 px после первой колонки и промежутка 120 px остаётся
580 px для текста. `margin: 0 auto` центрирует контейнер.

### Перекрывающиеся фотографии

У `.about__photos` стоят `position: relative` и высота 526 px. Это область для двух фотографий
размером 350 × 400 px. Первая располагается обычным образом в начале блока.

У `.about__video` стоит `position: absolute; right: 0; bottom: 0`. Поэтому второе фото привязано
к правому нижнему углу области, перекрывая первое. `relative` на родителе задаёт систему
координат для `absolute` у потомка.

Значок воспроизведения также расположен через `absolute`. Значения `top: 50%` и `left: 50%`
ставят его левый верхний угол в центр фотографии, а `translate(-50%, -50%)` сдвигает значок
на половину его собственного размера. В итоге центр значка совпадает с центром фотографии.
Значок воспроизведения в этом задании — часть вёрстки; воспроизведение видео не подключено.

### Текст и ссылка

Надзаголовок, основной заголовок, абзац и текст ссылки перенесены из макета.
`h2` обозначает заголовок секции, `p` — абзац. У ссылки `href="#programs"`: она прокручивает
страницу к элементу с `id="programs"`.

## 3. Блок «Лучшие программы для тебя»

Файлы находятся в `src/app/programs/`.

Здесь две колонки: текст шириной 580 px и фотоколлаж шириной 510 px. Между ними 90 px.
Фон секции — `#f3f5f4`, как в макете.

### Данные и interface

В `programs.component.ts` объявлен интерфейс:

```ts
interface Advantage {
  id: number;
  title: string;
  description: string;
  icon: string;
}
```

`interface` описывает форму объекта. У преимущества должны быть числовой идентификатор,
строковые заголовок, описание и путь к иконке. TypeScript проверяет эти типы при разработке;
сам интерфейс не создаёт объекты и не превращается в HTML.

Свойство `advantages: Advantage[]` содержит массив из трёх объектов: «Опытный гид»,
«Безопасный поход» и «Лояльные цены». Квадратные скобки в типе означают массив элементов
типа `Advantage`. Данные лежат в классе, разметка одной строки — в шаблоне.

### Как работает @for

```html
@for (advantage of advantages; track advantage.id) {
  <li class="programs__advantage">
    <img [src]="advantage.icon" alt="" width="50" height="50" />
    <div>
      <h3>{{ advantage.title }}</h3>
      <p>{{ advantage.description }}</p>
    </div>
  </li>
}
```

`advantages` — весь массив. `advantage` — текущий объект: сначала первый, затем второй,
затем третий. Для каждого объекта Angular создаёт один `li` с одинаковой структурой.

`track advantage.id` задаёт уникальный ключ. По нему Angular связывает объект с его элементом
DOM и при изменениях массива может сохранить и обновить нужную строку. DOM — представление
HTML в памяти браузера, с которым работает страница.

`{{ advantage.title }}` — интерполяция: Angular подставляет значение в текст HTML.
`[src]="advantage.icon"` — привязка свойства: Angular передаёт путь в свойство `src` изображения.
Кавычки здесь содержат выражение шаблона, а не буквальное имя картинки.

Иконки декоративные, поэтому у них пустой `alt`. Смысл преимущества уже передан соседним текстом.
У фотографий `alt` описывает изображённое место.

`@for` — встроенная конструкция Angular. Для этого цикла не нужен импорт `NgFor`.
Подробности есть в [официальном учебнике Angular](https://angular.dev/tutorials/learn-angular/5-control-flow-for).

### Четыре фотографии

```scss
.programs__photos {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 10px;
}
```

`repeat(2, ...)` создаёт две одинаковые колонки. `minmax(0, 1fr)` разрешает колонкам сжиматься
внутри доступной ширины. Четыре изображения автоматически занимают два ряда.

`aspect-ratio: 1` сохраняет квадратные пропорции. `object-fit: cover` заполняет область
фотографией с сохранением пропорций, при необходимости обрезая края.

У фотографий чередуются скруглённые углы: `border-radius: 0 50px` и `50px 0`.
Селектор `:nth-child(2)` выбирает второй элемент среди соседей, `:nth-child(3)` — третий.
Так получается расположение углов из макета.

## 4. Что изменено в шапке и первом экране

В `navbar.component.html` используется горный знак из оригинального логотипа.
Под ним название выводится из `companyName` через `{{ companyName }}`. Надпись внутри SVG
удалена, чтобы текст компании действительно зависел от свойства Angular-компонента.

У `.hero` минимальная высота 985 px. Фоновая фотография находится в `public/images/hero.png`.
Она уже затемнена, поэтому дополнительный затемняющий градиент не нужен.

Заголовок выровнен по левому краю контейнера. У формы полупрозрачный фон и `backdrop-filter`,
который размывает изображение за формой. У полей фон прозрачный.
Дата по-прежнему вводится стандартным `input type="date"`; описание его подписи есть в `README-UI.md`.

В `src/styles.scss` через `@font-face` подключены локальные файлы шрифтов.
Nunito Sans используется для текста страницы, Next Art — для названия компании.
`font-display: swap` позволяет сначала показать текст запасным шрифтом, пока основной загружается.

## 5. Анимация при наведении

Используется обычный CSS, без библиотек:

- У преимущества `:hover` меняет `transform` на `translateX(6px)` — строка сдвигается вправо.
- У фотографий `scale(1.02)` или `scale(1.03)` слегка увеличивает изображение.
- Кнопки при наведении меняют цвет фона и текста.

`transition` делает изменение плавным за 200 мс. `transform` меняет отображение элемента,
не передвигая соседние элементы в сетке. В обычном состоянии размеры блоков соответствуют макету.

`@media (prefers-reduced-motion: reduce)` отключает плавные переходы, если пользователь
выбрал уменьшенное движение в настройках устройства.

## 6. Адаптация к ширине экрана

`@media (max-width: ...)` применяет стили, когда ширина окна меньше указанного значения.
На узком экране две колонки становятся одной, отступы и шрифты уменьшаются. Фотографии
сохраняют пропорции, поля формы располагаются друг под другом.

В присланном файле использован десктопный макет. Перестроение на узких экранах — адаптация
этой композиции, а не воспроизведение отдельного мобильного фрейма.

## 7. Изображения и шрифты

Ресурсы сохранены локально, внешние адреса для показа страницы не требуются:

| Папка | Содержимое |
| --- | --- |
| `public/images` | Фон первого экрана, два фото похода и четыре фото программ |
| `public/icons` | Горный знак, значок воспроизведения и три иконки преимуществ |

Изображения, иконки и Next Art взяты из публичного
[набора ресурсов того же макета «РумТибет»](https://github.com/VladAleinikov/RumTibet)
и визуально сверены с открытым оригиналом Figma. Чужие HTML, CSS и JavaScript не использовались.
Nunito Sans получен из Google Fonts.

Файл из `public/images/about-cabin.png` доступен браузеру как `/images/about-cabin.png`:
папка `public` соответствует корню сайта. В адресе слово `public` писать не нужно.
