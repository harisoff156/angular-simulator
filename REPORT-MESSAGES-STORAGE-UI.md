# Отчёт: уведомления, хранилище и новые блоки

## Что сделано

- Созданы типы и сервис сообщений: уведомления появляются справа сверху, новые стоят первыми и закрываются через пять секунд или по крестику.
- Создан сервис для работы с `localStorage`; корневой компонент использует его для даты последнего посещения и счётчика.
- Добавлены блоки «Популярные направления» и «Блог о путешествиях» по присланным скриншотам.

## Типы сообщений

Файл `src/app/models/message.ts` содержит перечисление и интерфейс:

```ts
export enum MessageType {
  Success = 'success',
  Info = 'info',
  Warning = 'warning',
  Error = 'error',
}

export interface Message {
  readonly id: number;
  readonly text: string;
  readonly type: MessageType;
}
```

`enum` задаёт четыре допустимых типа сообщения. Например, `MessageType.Info` соответствует строке `'info'`. Интерфейс описывает форму объекта: числовой `id`, текст и тип. `readonly` запрещает повторное присваивание этих полей через TypeScript после создания объекта.

Чтобы использовать enum в HTML, недостаточно просто импортировать его в TypeScript: шаблон обращается к свойствам компонента. Поэтому в `AppComponent` есть `protected readonly messageType = MessageType`. После этого в шаблоне можно написать `messageType.Info`. `protected` оставляет свойство доступным шаблону и самому компоненту, а `readonly` защищает ссылку от переприсваивания.

## Сервис уведомлений

`src/app/services/message.service.ts` содержит `MessageService`. Декоратор `@Injectable({ providedIn: 'root' })` сообщает Angular, что сервис можно внедрять в компоненты и использовать один общий экземпляр приложения.

Внутреннее состояние скрыто с помощью `private`: `messageList` хранит массив, `nextId` — последнее выданное число, а `timers` связывает каждый id с его таймером. Геттер `messages` позволяет шаблону читать массив как `readonly Message[]`, не предоставляя публичный метод изменения массива.

```ts
public addMessage(text: string, type: MessageType): void {
  const message: Message = { id: ++this.nextId, text, type };
  this.messageList.unshift(message);

  const timer = setTimeout(() => this.closeMessage(message.id), 5000);
  this.timers.set(message.id, timer);
}
```

`++this.nextId` увеличивает счётчик и использует новое значение как id. `unshift` добавляет объект в начало массива, поэтому последнее сообщение показывается сверху. `setTimeout` запускает закрытие через 5000 миллисекунд. Таймер сохраняется в `Map`, чтобы его можно было отменить при ручном закрытии.

`closeMessage(id)` находит и отменяет таймер через `clearTimeout`, удаляет его из `Map` и создаёт новый массив с помощью `filter`, оставляя сообщения с другими id. `ngOnDestroy()` очищает оставшиеся таймеры при уничтожении сервиса. `void` означает, что метод не возвращает значение.

## Подключение сервиса и вывод шаблона

В конструкторе `AppComponent` Angular передаёт сервисы:

```ts
constructor(
  protected readonly messageService: MessageService,
  private readonly storage: StorageService,
) {
  this.saveLastVisitDate();
  this.saveVisitCount();
}
```

Это внедрение зависимостей: компонент получает готовые экземпляры от Angular. `messageService` нужен также в HTML, поэтому он `protected`; `storage` используется только внутри класса, поэтому он `private`.

Кнопка вызывает, например, `messageService.addMessage('Новая информация', messageType.Info)`. Сообщения выводятся в `app.component.html`:

```html
@for (message of messageService.messages; track message.id) {
  <ng-container [ngTemplateOutlet]="messageTemplate"
    [ngTemplateOutletContext]="{ $implicit: message }" />
}

<ng-template #messageTemplate let-message>
  <div class="message" [class]="'message message--' + message.type">
    <span class="message__text">{{ message.text }}</span>
    <button type="button" (click)="messageService.closeMessage(message.id)">×</button>
  </div>
</ng-template>
```

В отчёте приведён сокращённый фрагмент: в файле у кнопки также есть класс и подпись для программ чтения экрана. `@for` проходит по сообщениям, а `track message.id` помогает Angular различать элементы. `ng-template` описывает разметку одного сообщения, но сам по себе её не выводит. `NgTemplateOutlet` создаёт её внутри цикла, передавая объект через `$implicit`; `let-message` получает этот объект. `{{ message.text }}` выводит текст, а `(click)` вызывает закрытие.

Класс вроде `message--info` получается из типа и задаёт цветную полоску. В `app.component.scss` контейнер `.messages` имеет `position: fixed`, `top` и `right`: он остаётся справа сверху при прокрутке. `z-index` размещает его над страницей. Анимация появления отключается при системной настройке уменьшения движения.

## Сервис локального хранилища

Файл `src/app/services/storage.service.ts` содержит четыре публичных метода:

```ts
public setItem<T>(key: string, value: T): void {
  localStorage.setItem(key, JSON.stringify(value));
}

public getItem<T>(key: string): T | null {
  const value = localStorage.getItem(key);
  if (value === null) return null;
  try {
    return JSON.parse(value) as T;
  } catch {
    return value as T;
  }
}
```

`<T>` — параметр типа: например, `setItem<number>('visitCount', 1)` принимает число. Хранилище браузера хранит строки, поэтому `JSON.stringify` превращает поддерживаемое JSON значение в строку, а `JSON.parse` восстанавливает его. Если ключа нет, возвращается `null`. Если сохранённая ранее строка не является JSON, `catch` возвращает её как есть для совместимости со старой записью.

`as T` сообщает TypeScript ожидаемый тип, но не проверяет данные во время выполнения: тип при чтении должен соответствовать сохранённому значению. JSON подходит для обычных строк, чисел, массивов и объектов, но не сохраняет произвольные экземпляры классов и методы без потери типа. `removeItem(key)` удаляет один ключ, а `clear()` очищает всё локальное хранилище сайта.

В `AppComponent` метод `saveLastVisitDate()` сохраняет строку даты через сервис. `saveVisitCount()` читает значение, преобразует его в число, проверяет `Number.isFinite` и увеличивает на единицу. Оба метода вызываются при создании компонента.

## Популярные направления

Компонент находится в `src/app/destinations/`. Декоратор `@Component` задаёт имя тега `app-destinations` и пути к HTML и SCSS. Массив `destinations` хранит id, название, описание, цену, рейтинг и путь к изображению каждой карточки. В шаблоне `@for` создаёт карточку для каждого объекта. `[src]` и `[alt]` связывают атрибуты изображения с данными, а `{{ destination.title }}` выводит название.

В стилях `display: grid` и `repeat(3, minmax(0, 1fr))` создают три равные колонки. Карточка имеет `position: relative`; рейтинг и нижняя плашка расположены внутри неё с помощью `position: absolute`. `object-fit: cover` заполняет карточку фотографией с сохранением пропорций. В `@media` при ширине до 800 пикселей карточки переходят в одну колонку.

## Блог о путешествиях

Компонент `src/app/travel-blog/` работает так же: массив `articles` хранит данные четырёх карточек, а `@for` выводит их в HTML. В каждой карточке есть изображение, заголовок, описание, дата и кнопка. Тег `time` хранит дату в машиночитаемом `datetime`.

На широком экране CSS Grid создаёт две колонки. Внутри карточки Flex располагает изображение и текст рядом; на узком экране правила `@media` перестраивают карточки и изображение становится над текстом. Псевдокласс `:hover` задаёт оформление при наведении.

Оба компонента объявляют `showMessage = output<string>()`. При нажатии `showMessage.emit(...)` отправляет строку родительскому компоненту. В `app.component.html` обработчик `(showMessage)` получает её как `$event` и передаёт в `messageService.addMessage($event, messageType.Info)`. Сейчас кнопки статей и дополнительных материалов показывают уведомление; отдельные страницы статей не реализованы. Ссылка «Блог» в навигации ведёт к `id="blog"`.

## Как проверить

1. Запустите проект командой `npm start` и откройте адрес, который покажет Angular, обычно `http://localhost:4200`.
2. Проверьте новые блоки и уменьшите ширину окна: карточки должны перестроиться.
3. Нажмите несколько кнопок уведомлений подряд: новое сообщение должно появиться сверху. Закройте одно крестиком, а остальные дождитесь через пять секунд.
4. В инструментах разработчика откройте Application → Local Storage и найдите `lastVisitDate` и `visitCount`. Перезагрузите страницу: дата обновится, счётчик увеличится.

Сборка после добавления компонентов прошла. Встроенный браузер не смог подключиться к локальному серверу, поэтому визуальное соответствие и нажатия в нём не проверены. Фотографии вырезаны из присланных скриншотов, поэтому их качество ограничено исходным разрешением. Автоматические тесты сервисов добавлены, но предыдущий запуск Vitest завис до вывода результата; считать их пройденными нельзя.
